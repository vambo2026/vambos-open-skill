# 有人味的页面设计

用于新建网站、产品页面、工作台与应用界面，或用户提出“AI感太重”“像模板”“没有个人特色”时。作为视觉与产品设计补充，配合项目实际技术栈；不替代开发、部署技能。

## 先判断，再编码

1. 阅读现有页面、真实内容、用户参考与项目约束。确认主要使用者、首要行动、内容成熟度和用户想表达的性格。已有答案不重复追问；只在关键方向无法判断时问一个问题。
2. 开工前用简短文字说明四件事：视觉方向、信息顺序、组件边界、交互。项目需要架构说明时附图。不要把设计讨论扩成与当前任务无关的审批流程。
3. 用三个具体词定义气质，并给出实现依据。例如“温暖、好奇、手作”：真实工作场景、可探索的项目预览、少量手写注释。不要只写“高级、现代、简洁”。
4. 选择最符合内容的一种构图主线，而非先套通用模板。个人主页可以围绕创作环境和作品；工具围绕输入与结果；工作台围绕任务、信息密度和反馈。用户明确的参考和限制优先。

## 内容决定形式

- 首屏回答“这是谁/这是什么、能给我什么、接下来能做什么”。是否需要主视觉、主视觉多大，由内容与目的决定。
- 优先让真实作品、产品状态、截图、文字和数据成为视觉主体。缺素材时缩小空位或给出有用的空状态；不要用巨大空白和装饰填充。
- 不编造上线项目、客户、评价、阅读量、发布日期、完成进度或联系地址。将正式内容、可运行原型、概念预览和筹备计划明确区分。
- 作者未提供或确认的经历、城市、身份与个人叙述不得当成事实；需要时使用明确待补充状态。生成的概念场景不可冒充真实生活照片。
- 项目类别真正不同时，可分别使用图表、档案、棋盘、海报或播放器等视觉语言；重复的同类任务保持一致布局，不为“独特”破坏可扫描性。
- 文案具体、简短、自然，尽量使用用户自己的语言。保留有意义的个人表达；删掉换一个网站名字也能照搬的口号。

## 降低模板感的具体做法

- 不默认使用渐变大字、紫蓝光晕、玻璃卡片、全屏巨型标题、统一bento宫格、药丸标签堆叠、无意义角标、装饰英文和每段一个图标。这些不是禁用项，但每次使用都应有品牌、内容或交互理由。
- 不把“去AI感”简单等同于全白极简、故意粗糙或随机不对称。可以丰富、温暖、严肃或有戏剧性，关键是设计选择来自当前项目。
- 建立有限的颜色、字号、间距、圆角和阴影规则。用主次关系组织注意力，避免每个元素都抢眼。中文字体、字距、断行与英文混排必须单独检查。
- 主操作有明确视觉优先级。减少重复CTA；次要信息降低对比但保持可读性。每块内容都应有用途，无用途的装饰优先删除。
- 选择一两个有记忆点的细节，例如作品本身的微交互、与主题有关的材质或构图；不要把所有设计技巧堆在一页。

## 交互必须有结果

- 悬停、展开、筛选、搜索、播放、下载应真正工作，且按钮文案准确描述结果。卡片内多个动作避免嵌套链接与点击冲突。
- 原型只能声称自己实际实现的功能。合成声音不冒充音乐作品，情景计算不冒充真实预测，计划介绍不冒充视频播放。
- 使用有限的位移、透明度和状态过渡；避免每个区块轮番飞入。支持 prefers-reduced-motion；移动端和键盘用户无需悬停也能完成主要操作。
- 完整处理加载、空、失败、选中与禁用状态。弹窗支持键盘关闭、焦点管理与恢复。音频只在用户主动操作后播放，并可立即停止。

## 验收与交付

1. 运行适合改动范围的构建和功能验证。涉及主要交互时验证输入、结果、错误和返回路径。
2. 查看实际渲染的桌面与手机截图，不能只看代码或以自动测试代替视觉检查。关键断点检查溢出、断行、图片裁切、文字对比、触摸目标、弹窗与深色主题（如有）。
3. 用下面的问题复核并直接修正明显问题：
   - 去掉名称后，这一页是否仍像这个人/这个产品？特色由什么真实内容支撑？
   - 是否出现没有信息价值的空白、口号、标签、图标或大标题？
   - 用户能否迅速找到主要内容并完成主要行动？
   - 区块形式是否服务于内容，而非只是好看？
   - 所有可点击元素是否有真实结果，状态与承诺是否相符？
4. 如用户已授权开发和发布，完成验证后按现有交付流程继续，不额外添加设计审批。若用户要求先看图，则交付预览等待其设计选择。
5. 汇报具体改动、验证结果和尚缺真实素材。不要声称用户已认可审美；把视觉反馈留给用户。

## 反馈迭代

当用户只说“AI感太重”，先从截图中指出两三个可观察问题，例如标题过大、装饰重复、内容被挤到第二屏，再修改。不用“更高级”替代具体方案，也不重复把页面换成另一套通用模板。
